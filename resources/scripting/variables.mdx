---
title: "Variables"
description: "All available variables within bleed."
icon: "signature"
---

These variables are accessible throughout bleed and can be used
in any command context which contains a `message` or `embed code` parameter (e.g. `welcome`, `goodbye` & `boost`)

<Warning>
  Variables must be written exactly as shown, without any spaces inside the brackets. Keep in mind that
  misspelled variables will not cause an error. They will appear as raw text instead.
</Warning>

<AccordionGroup>

    | `{guild.role_count}`              | The guild's role count                                               |

    | `{user.name}`                  | The user's name                                        |

    | `{user.joined_at_timestamp}`   | The user's guild join date in UNIX                     |

    | `{user.created_at_timestamp}`  | The user's account creation date in UNIX               |
    | `{user.display_name}`          | The user's current display name                        |
    | `{user.boost}`                 | `Yes`/`No` if the user is boosting the guild           |

    | `{user.color}`                 | The user's top role hex code                           |
    | `{user.top_role}`              | The user's top role name, defaults to N/A              |

      Variables in UNIX can be used with Discord timestamps, such as `<t:{user.created_at_timestamp}:R>`, which will display as **3 years ago**.

  <Accordion title="Bump Reminder">
    <Info>
      This section is only available for the `bumpreminder` command.
    </Info>
    | Variable                         | Output                                 |
    | -------------------------------- | -------------------------------------- |
    | `{bumpreminder.last_user_bump}`  | The last user to bump the server       |
    | `{bumpreminder.next_bump}`       | A relative timestamp for the next bump |
    | `{unix(bumpreminder.next_bump)}` | The next bump in UNIX                  |

    <Tip>
      `<t:{unix(bumpreminder.next_bump)}:t>` will display the time of the next bump, such as **4:30 PM**.
      In the reminder message, this is the time the reminder was sent.
    </Tip>
